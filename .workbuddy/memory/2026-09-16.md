### ★ 中间件知识点的诚实口径（本项目零中间件，重要）
用户要「服务器依赖中间件的高水平知识点写进简历」。本项目**刻意零中间件**（JSONL 替代 MySQL、进程内 BM25 替代 ES/向量库、stdio 子进程替代 gRPC），所以**绝不能**写「用了 Redis 锁 / RocketMQ 异步」。
正确写法 = 写「中间件选型能力」：论证不同规模下该引入什么、为什么，以及不引入时靠什么兜住。第七节覆盖 7 块：
1. 持久化：事件流 vs 实体表；何时换 MySQL（多端共享/查询分析/QPS）→ Event Sourcing + CQRS 快照读模型
2. 检索：字面匹配用 BM25（IDF 惩罚高频词），语义型才上向量 HNSW，工业标准 = BM25+向量混合召回 + cross-encoder rerank
3. Redis 四用法：同会话互斥锁（**Fencing Token 补 GC pause 下锁失效**）、requestId 幂等键（SET NX EX 原子，不能 GET 再 SET）、热会话缓存（击穿/穿透/雪崩）、流式输出 Stream vs Pub/Sub
4. MQ：为何同步阻塞；长任务与副作用执行；三段式不丢（confirm/持久化/手动 ack）+ 幂等消费
5. 通信：stdio vs gRPC；**stdio 缓冲区打满导致双向死锁**必须开独立读线程
6. 可观测：JSONL trace → OpenTelemetry + Prometheus；trace/metric/log 分工；高基数标签不能进 metric
7. ★ Agent 特有风险：密钥只从环境变量读——Agent 会把文件内容读进上下文，key 写进配置文件会被 read_file 带进 prompt→会话日志→Trace→模型厂商，**不可逆多点泄露**
